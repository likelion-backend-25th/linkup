## 1. 결정 상태 (Status)

- 채택됨 (Accepted)

## 2. 배경 및 맥락 (Context)

- 2주간의 개발 기간 동안 안정적인 클라이언트 서빙과 안전한 VIP 구독 결제 시스템을 구축해야 하는 과제 직면.

## 3. 검토 대안 (Alternatives Considered)

- 프론트엔드 배포
    - 옵션 A : AWS S3 + CloudFront
    - 옵션 B : Vercel 플랫폼 연동
    - 옵션 C : Nginx 컨테이너 기반 호스팅(Docker Compose 연계)

- 결제 솔루션
    - 옵션 A : 토스페이먼츠 직접 연동
    - 옵션 B : 포트원 통합 결제

## 4. 최종 결정 사항 (Decision)

- 프론트엔드 배포: S3 + CloudFront
- 결제 솔루션: 토스페이먼츠

## 5. 선택 이유 (Rationale)

- 기술적 적합성
    - S3 + CloudFront
        - React + TypeScript + Vite로 빌드된 정적 파일을 S3에 저장하고, CloudFront CDN을 통해 사용자에게 제공하는 방식.
        - 별도의 프론트엔드 서버를 운영하지 않아도 되므로 서버 관리 부담이 적으며, 정적 파일 중심의 React 애플리케이션에 적합함.
        - CloudFront의 캐싱을 통해 반복적인 정적 파일 요청을 줄일 수 있어 페이지 로딩 성능과 서비스 안정성을 확보할 수 있음.
        - AWS 기반의 백엔드 및 배포 환경과 연계하기 용이하여 프로젝트 전체 AWS 인프라 구성과 일관성을 유지할 수 있음.
    - 토스페이먼츠
        - 결제 API와 SDK를 제공하여 VIP 구독 결제 기능을 구현하기에 적합함.
        - 백엔드와 연동하여 결제 승인 및 결제 상태를 관리할 수 있음.
        - 백엔드, 프론트엔드 샘플 코드를 제공받을 수 있기 때문에 플로우를 빠르게 이해해 서비스에 도입을 할 수 있음.
- 비용 및 유지보수
    - S3  + CloudFront
        - 별도의 프론트엔드 서버 없이 운영이 가능함
        - 사용량에 따른 비용 구조로 불필요한 서버 운영 비용 감소함
    - 토스페이먼츠
        - 별도의 결제 시스템을 직접 구현할 필요가 없어 개발 비용 및 유지 보수 부담을 줄일 수 있음
- 보안성
    - S3 + CloudFront
        - S3 퍼블릭 접근을 제한하고 CloudFront OAC 및 HTTPS를 적용하여 정적 파일 접근과 통신을 보호함
    - 토스페이먼츠
        - 결제 관련 민감 정보를 직접 처리하는 범위를 줄이고, 결제 승인 및 검증을 백엔드에서 수행하여 결제 요청의 무결성을 확보함

## 6. 결과 및 영향 (Consequences)

**구현 및 배포 후 결과를 바탕으로 작성 예정**

- 긍정적 효과:
    - 프론트엔드 배포
        - S3 + CloudFront 기반의 정적 파일 배포 구조를 검토하고 AWS 인프라를 활용한 프론트엔드 배포 방식을 학습할 수 있었음
        - 프론트엔드와 백엔드를 분리하여 배포하는 구조를 이해하고, CDN을 활용한 정적 파일 제공 방식에 대한 경험을 확보할 수 있었음
        - AWS 기반의 백엔드 환경과 프론트엔드 배포 환경을 연계하는 과정에서 실제 배포 아키텍처에 대한 이해도를 높일 수 있었음
    - 결제 솔루션
        - 토스페이먼츠 API를 활용하여 구독 결제, 결제 승인 및 결제 상태 관리에 필요한 흐름을 설계하고 구현할 수 있었음.
        - 결제 요청부터 백엔드 승인 및 결제 정보 저장까지 결제 시스템의 기본적인 처리 흐름을 이해할 수 있었음.
        - 외부 PG사의 API를 백엔드와 연동하면서 외부 서비스 연동 방식과 예외 상황 처리에 대한 경험을 얻을 수 있었음.
        
- 한계점 및 향후 개선 과제:
    - 프론트엔드 배포
        - 실제 프로젝트에서 이미지 업로드 및 정적 리소스 관리 등을 구현하는 과정에서 S3 + CLoudFront 환경에 대한 추가적인 설정과 관리가 필요했음.
        - 발표 피드백을 통해 현재 프로젝트의 개발 기간과 구현 범위를 고려했을 때, Vercel을 활용한 프론트엔드 배포 방식이 프로젝트의 요구사항에 보다 적합할 수 있다는 의견을 확인함.
        - 향후에는 개발 기간, 이미지 및 정적 파일 처리 방식, 배포 편의성 등을 종합적으로 고려하여 Vercel과 같은 프론트엔드 배포 플랫폼을 우선적으로 검토할 수 있게 됨.
    - 결제 솔루션
        - 토스페이먼츠를 직접 연동하는 과정에서 결제 인증 및 추가 인증 절차 등 구현해야 할 결제 흐름이 존재하여, 제한된 개발 기간 내에서 구현 복잡도가 높아지는 한계가 있었음.
        - 발표 피드백에서는 포트원이 다양한 PG사를 통합하여 사용할 수 있고 결제 UI 및 관련 기능을 제공하기 때문에 현재와 같은 단기간의 프로젝트에서는 구현 부담을 줄일 수 있다는 의견이 있었음.
        - 향후 유사한 프로젝트에서는 개발 기간과 구현 난이도를 고려하여 포트원과 같은 통합 결제 솔루션도 함께 검토하고, 필요한 결제 UI 및 인증 절차를 제공받을 수 있는지를 비교하여 선정할 필요가 있음.
